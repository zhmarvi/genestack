# ceph_rgw_object_store

Registers an external Ceph RADOS Gateway as the OpenStack `object-store` service
so that Swift API clients are directed at RGW.

This role does not deploy Swift. RGW implements the Swift API natively, so the
OpenStack side only needs a service catalog entry and the Keystone service user
that RGW authenticates as when it validates tokens. Deploying the Swift chart
alongside this is neither required nor useful; leave `swift: false` in
`openstack-components.yaml`.

## What it does

1. Reads the Keystone service user password from the `swift-admin` secret
   (generated by `bin/create-secrets.sh`), or takes it from
   `rgw_keystone_password`.
2. Creates or updates the `swift` Keystone user in the service project and
   grants it the `admin` role.
3. Ensures the roles RGW accepts exist (`admin`, `member`, `swiftoperator`).
4. Ensures the `object-store` service entry exists, named `swift`.
5. Creates or updates the public, internal, and admin endpoints. Existing
   endpoints are updated in place so a changed RGW address is corrected rather
   than duplicated.
6. Prints the matching `ceph config set client.rgw ...` commands to apply on the
   Ceph cluster, then optionally queries the account to verify.

## Usage

```shell
ansible-playbook /opt/genestack/ansible/playbooks/deploy-rgw-object-store.yaml \
  -e rgw_public_url=https://objects.your.domain.tld
```

## The pairing that matters

Two variables must agree with the external Ceph cluster or every object request
returns 404 rather than failing visibly:

| Role variable | Ceph setting |
|---|---|
| `rgw_swift_url_prefix` | `rgw_swift_url_prefix` |
| `rgw_swift_account_in_url` | `rgw_swift_account_in_url` |

With `rgw_swift_account_in_url: true` the endpoint path becomes
`/swift/v1/AUTH_%(tenant_id)s`; with `false` it is `/swift/v1`. Account in URL
is required for cross-project bucket access.

The role writes `%(tenant_id)s` rather than `$(project_id)s`. Both are valid
Keystone substitutions, but `$(...)` is command substitution in a shell and gets
silently emptied if the URL is ever passed through one unquoted.

## Variables

See `defaults/main.yml`. `rgw_public_url` is required; everything else has a
working default.

## Known limitation

Ceilometer object storage metering does not work against RGW. The
`swift_account` resource type and the request-class meters in
`base-helm-configs/ceilometer/ceilometer-helm-overrides.yaml` depend on
`ceilometermiddleware` running inside a Swift proxy and publishing
oslo.messaging notifications. RGW has no equivalent; its bucket notifications
use a different mechanism and format. Confirm nothing depends on those meters
before switching an existing deployment to RGW.
